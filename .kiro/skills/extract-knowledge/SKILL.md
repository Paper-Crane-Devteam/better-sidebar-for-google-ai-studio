# 对话知识提取 Skill

## 目的

在长对话中，很多有价值的结论、架构决策、排查经验会淹没在大量中间过程里。
这个 skill 帮助你从对话中提取精华，保存为结构化文档，方便日后查阅。

## 输出位置

所有提取的知识文档保存在：`.kiro/user-knowledge/`

## 触发方式

当用户说以下类似的话时激活：
- "总结一下这次对话的重要结论"
- "把刚才的方案记录下来"
- "提取精华"
- "帮我记住这个"
- "沉淀一下经验"

## 提取规则

### 应该提取的内容

1. **架构决策** — 为什么选择某种方案、权衡了什么
2. **设计方案** — 最终确定的方案细节（不是中间讨论过程）
3. **排查结论** — Bug 的根因和修复方式
4. **踩坑经验** — 遇到的坑和解决方法，供下次参考
5. **关键配置** — 不容易记住的配置项、命令、URL
6. **流程说明** — 某个业务/技术流程的最终理解

### 不应该提取的内容

- 中间反复试错的过程
- 临时性的调试命令（除非有通用参考价值）
- 纯粹的代码改动（代码在 git 里，不需要重复记录）
- 已经在代码注释或 README 中体现的内容

## 文档格式

文件名格式：`YYYY-MM-DD-<简短主题>.md`

示例：`2026-06-12-boss-callback-race-condition.md`

### 模板

```markdown
# <标题>

> 提取自 Kiro 对话 · <日期>

## 背景

简述这次对话要解决什么问题或讨论什么主题。

## 关键结论

用简洁的要点列出最重要的结论/决策/发现。

- 结论 1
- 结论 2
- ...

## 详细说明

（可选）如果某些结论需要更多上下文，在这里展开。

### 子标题 1

详细内容...

## 相关文件

列出涉及的关键文件路径，方便日后定位。

- `path/to/file1`
- `path/to/file2`

## 标签

`#tag1` `#tag2` `#tag3`
```

## 执行流程

1. **回顾对话** — 浏览整个对话历史，识别有价值的内容
2. **分类归纳** — 按上述"应该提取的内容"分类
3. **精炼表达** — 用简洁清晰的语言重新组织（不是复制聊天原文）
4. **生成文档** — 按模板生成 markdown 文件
5. **保存文件** — 写入 `.kiro/user-knowledge/YYYY-MM-DD-<主题>.md`
6. **告知用户** — 展示提取了哪些关键知识点，让用户确认是否需要补充

## 多主题处理

如果一次对话涉及多个不相关的主题，应该拆分成多个文件。
例如一次对话既讨论了审批流程设计，又排查了 Higress 路由问题，
应该生成两个文件。

## 追加更新

如果 `.kiro/user-knowledge/` 中已有同主题的文件，优先追加更新而不是新建。
在文件末尾添加新的段落，标注更新日期。

## 索引维护

每次新增或更新文档后，检查是否存在 `.kiro/user-knowledge/INDEX.md`。
如果存在，更新索引；如果不存在，创建索引文件：

```markdown
# 知识库索引

| 日期 | 主题 | 标签 | 文件 |
|------|------|------|------|
| 2026-06-12 | Boss 回调竞态条件 | #approval #boss #race-condition | [链接](./2026-06-12-boss-callback-race-condition.md) |
```
